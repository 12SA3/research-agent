Agent 与数字孪生风险治理清单

一、适用范围

本清单适用于当前校园数字孪生项目中的两类 Agent：参与 Vue 3、TypeScript、ThingJS 2.0 研发的编码 Agent，以及运行在产品中的查询、研判或操作 Agent。治理目标不是消除所有不确定性，而是让每项风险都有责任人、技术控制、验证证据和可恢复路径。数字孪生连接空间、实时数据和潜在物理控制，故同一错误可能同时表现为代码缺陷、欺骗性画面、错误业务判断和现实影响。

NIST IR 8356 指出数字孪生同时继承传统网络安全问题并引入新的信任问题。NIST 2026 年研讨总结将互操作、验证确认与不确定性量化、网络安全和人才能力列为持续障碍。治理时应把 Agent 看成新的决策与工具调用入口，而不是单纯的代码补全插件。

二、风险分级

低风险：只读检索、摘要、文档格式、Mock 草案、静态分析建议。失败影响可通过人工阅读发现，且不改变运行状态。

中风险：修改业务代码、接口适配、创建 Marker、调整样式、生成测试。可能引起回归，但可在分支、Mock 和场景测试中恢复。

高风险：修改业务切换状态机、层级与坐标、全局事件、模型资源、权限、生产配置、数据迁移或发布。错误可能跨模块或难以从画面发现，必须先审批方案。

禁止自主执行：真实门禁、消防、配电、安防处置，删除未知用户数据，绕过安全控制，向外部模型上传敏感人员信息，或在没有验证证据时自动发布。Agent 可提供建议，但确定性策略、人类审批和审计不可省略。

三、核心风险与控制

1. SDK 与架构幻觉。表现为虚构 ThingJS API、调用私有字段、越过 SDK 写 Three.js、按照过期 README 新建 `src/stories`。控制措施：建立项目能力卡；检索顺序固定为项目规则、相似实现、官方 API；无法找到证据就停止；CI 禁止已知私有字段和未授权底层图形调用。验收证据包括 API 来源链接、类型检查、真实场景运行和代码评审。

2. 空间语义错误。表现为世界坐标当局部坐标、同名 Floor 串楼、对象 parent 错误、Marker 在错误层级显示。控制措施：统一 `LevelInfo`；数据必须包含建筑、楼层和实体 ID；创建对象前记录 parent 与坐标系；Floor 下世界坐标显式转换；测试同名楼层和多建筑。此类错误不能只靠编译或单截图判断。

3. 生命周期与资源泄漏。表现为重复 `on`、未 `off`、Marker DOM 残留、逐帧 update、定时器、音频和轮询不停止。控制措施：每个功能声明资源所有者；创建时同步登记清理；事件必须有 tag；业务退出、层级离开、组件卸载和异常路径都调用幂等 destroy；自动测试重复进入退出五至十次并比较对象、DOM、事件、网络和堆基线。

4. 异步竞态。表现为旧接口响应覆盖新业务、模型加载后操作已销毁 App、漫游取消后继续播报、快速切换时旧 mounted 完成。控制措施：序列号、AbortSignal、有限超时和最终状态判断；只有成功完成才提交业务状态；切换时先使旧 runId 失效再回收；测试慢响应、乱序、取消和连续点击。项目已有 `switchSeq`、等待器和安全销毁，可作为统一模式。

5. 视觉误判。表现为代码和测试通过但 Marker 被遮挡、颜色语义错误、相机穿模、Z-fighting 或大屏比例失真。控制措施：固定相机、浏览器、分辨率、数据和字体；等待连续画面稳定；结合像素差、对象状态和人工体验验收；视觉基准更新需说明需求原因。不同 GPU 的抗锯齿差异不能被当作业务回归，也不能用过大容差掩盖真实问题。

6. 性能退化。表现为帧率下降、主线程阻塞、纹理或 DOM 过多、切层越来越慢。控制措施：目标设备设预算；采集冷启动、切层、业务切换和漫游阶段；优先消除重复对象、监听和轮询，再调整画质；检查高 DPI、纹理、Marker 数和逐帧逻辑。Agent 不得以关闭阴影或降低分辨率作为无数据的默认“优化”。

7. 数据质量与欺骗性表示。表现为过期 WebSocket 值仍显示为实时、缺失字段被补成零、告警时间错乱、预测没有置信区间。控制措施：每条关键数据携带来源、采集时间、接收时间、质量、新鲜度和单位；空值与零分开；断线和过期在 UI 明示；不确定性进入研判结果。画面真实感越强，越需要显式提醒数据并非现实本身。

8. 提示注入与工具滥用。网页、接口、工单和模型元数据中的文本都可能包含恶意指令。控制措施：数据与指令通道分离；工具采用白名单和强参数校验；默认只读；写操作限制资源和范围；敏感动作二次确认；记录每次工具调用与结果。不能依赖模型“自行识别所有攻击”，防御应覆盖权限、运行环境、监控和人工流程。

9. 隐私与合规。宿舍项目涉及人员、房间、入住、监控和查寝信息。控制措施：最小化输入；脱敏 ID；外部模型禁传生产原始数据；按角色限制查询；对提示、输出、缓存和日志设置留存周期；测试数据使用合成或脱敏样本。Agent 输出面板也要继承原系统权限，不能因自然语言入口扩大可见范围。

10. 自动化偏见与责任模糊。表现为把建议当事实、无人对最终操作负责、Agent 错误被归咎于“模型”。控制措施：为每项任务指定业务、3D、数据和审批责任人；输出区分事实、推断和建议；关键研判显示来源；高风险决策保留人工签名；供应商或模型升级后重新评测。Digital Twin Consortium 对可信 Agent 的讨论同样强调人类控制、透明、安全和隐私。

11. 供应链和模型变化。模型、插件、npm 包、ThingJS 版本、场景资源和浏览器更新都可能改变行为。控制措施：锁定依赖和工具版本；保存 Agent 轨迹与任务基线；新模型跑固定回归和新鲜盲测；第三方连接器按权限审计；禁止 Agent 私自安装未知包。不能用公开榜单替代本仓库评测。

12. 文档漂移。当前 README 的 Story 架构与实际 Manager 主线不一致，是现实样例。控制措施：OpenSpec 为能力事实源，README 只做索引；接口文档、Mock、类型和配置做一致性检查；架构变化必须同提交更新；注释掉的大段旧实现迁出主代码。Agent 在发现冲突时应报告差异，不自行选择更符合其先验的版本。

四、发布前检查清单

需求：是否写明物理对象、业务目的、层级、数据来源、成功标准和禁止行为。设计：是否写明 parent、坐标系、对象所有者、事件 tag、取消点、权限和回滚。代码：是否只用有证据的 API，是否保护用户已有改动，是否避免深度代理 3D 实例。测试：构建、契约、层级、重复进入、失败、取消、视觉、性能和安全是否有结果。数据：时间、单位、空值、质量和权限是否明确。交付：差异、截图、指标、未测项和人工验收是否可追踪。

五、运行时监控与应急

上线后监控业务切换失败、层级超时、WebSocket 断线、接口错误、对象数、DOM 数、长任务、内存、Agent 工具拒绝、审批和撤销。设定停止开关：运行时 Agent 可立即降级为只读搜索；写工具可单独禁用；业务场景可回退到无 Agent 的确定性操作。事故响应顺序为隔离权限、保存轨迹和数据快照、回滚、复现、确定物理与信息影响、补评测任务，而不是先修改提示词掩盖症状。

六、治理结论

最有效的治理不是堆叠一份通用安全提示，而是把项目已有的层级、业务生命周期、接口契约和场景清理转成机器可执行约束。编码 Agent 先在分支和 Mock 环境证明能力；运行时 Agent 先只读、后建议、再审批执行。任何走向自主控制的升级都必须以数据可信、策略确定、权限可撤销、过程可审计和结果可验证为前提。
